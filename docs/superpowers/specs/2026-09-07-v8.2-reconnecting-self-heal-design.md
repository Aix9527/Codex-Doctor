# Codex Doctor V8.2.0 Reconnecting 专项自愈设计

## 目标

把 Codex Doctor 从“能诊断网络、能修改代理、能重启 Desktop”升级为针对 **Codex / ChatGPT Desktop 持续 Reconnecting** 的端到端闭环：检测 → 选择可用网络路径 → 安全修复 → 重启 Desktop → 重新验证 → 给出明确终态。

## 范围

V8.2.0 只解决 Reconnecting 自愈闭环，不扩展账号、模型、会话内容、更新源或第三方安装器能力。

## 核心流程

```text
用户点击 Reconnecting 自愈
→ 建立修复前快照
→ 运行 discovery + diagnosis
→ 判断直连/代理/TUN/Git/npm/.codex/.env 状态
→ 生成受限 SelfHealPlan
→ 仅执行白名单动作
→ 写配置前备份
→ 必要时重启扫描确认的 Desktop
→ 重新 discovery + diagnosis
→ 端到端复检
→ 输出 RECOVERED / NETWORK_RECOVERED / PROXY_FAILED / DNS_FAILED / TLS_FAILED / DESKTOP_RESTART_FAILED / MANUAL_REQUIRED
```

## 设计原则

1. **不靠进程存在判定恢复。** Desktop 重新启动只是中间步骤，最终结果必须由修复后的网络诊断和 Desktop 运行状态共同决定。
2. **直连优先，代理有证据才写。** 直连 TLS 可用时不写代理；只有显式代理 HTTPS 已验证成功时，才允许把该代理写入 `.codex/.env`。
3. **写前备份，失败回滚。** `.codex/.env` 修复继续保留无关键值并生成备份；执行后验证失败必须恢复备份。
4. **不写 Windows 用户代理默认值。** V8.2.0 继续保持用户级 HTTP_PROXY/HTTPS_PROXY 默认不自动写入。
5. **Git/npm 只处理已判定冲突。** 不清理无关配置。
6. **Desktop 只操作 discovery 确认的 EXE/PID。** 不按标题或模糊名称结束未知进程。
7. **ManualRequired 不伪报成功。** DNS、TLS、代理、权限或 Desktop 无法验证时输出明确分类。

## 新增模型

新增 `ReconnectingRecoveryStatus`：

- `Recovered`
- `NetworkRecovered`
- `ProxyFailed`
- `DnsFailed`
- `TlsFailed`
- `DesktopRestartFailed`
- `ManualRequired`

新增 `ReconnectingRecoveryResult`，至少包含：

- `Status`
- `BeforeScanId`
- `AfterScanId`
- `Actions`
- `SummaryZh`
- `DiagnosisBefore`
- `DiagnosisAfter`

新增 `ReconnectingSelfHealPlan`，只允许组合以下动作：

- `codex.proxy.env`
- `git.proxy.clear`
- `npm.proxy.clear`
- `codex.desktop.restart`

不允许任意命令字符串进入计划。

## 判定规则

### RECOVERED

满足全部条件：

- 修复后存在可用网络路径；
- discovery 确认目标 Desktop 正在运行；
- 无新的 Critical/Urgent 网络 blocker。

### NETWORK_RECOVERED

- 修复后网络路径已可用；
- 但 Desktop 重启/运行验证仍失败。

### PROXY_FAILED

- 直连不可用；
- 需要代理；
- 但候选代理均未通过 HTTPS 验证或写入后复检失败。

### DNS_FAILED

- DNS 仍失败，且代理路径也无法形成可验证的替代路径。

### TLS_FAILED

- DNS 正常；
- 直连 TLS 失败；
- 无可验证代理替代路径。

### DESKTOP_RESTART_FAILED

- 网络已恢复；
- 但扫描确认的 Desktop 无法重新启动或启动后 discovery 仍未确认运行。

### MANUAL_REQUIRED

用于权限不足、状态歧义、无法安全决定动作或复检数据不完整。

## UI

主界面增加按钮：`Reconnecting 自愈`。

点击后：

1. 禁用会改变状态的主要按钮；
2. 显示阶段进度；
3. 运行自愈；
4. 将每个动作、验证结果和最终分类写入日志；
5. 完成后刷新主扫描结果；
6. 若非 `Recovered`，提示用户导出完整报告。

不新增常驻后台服务，不自动无限重试。

## 报告

健康报告增加 `reconnectingRecovery` 节点，记录：

- 修复前/后 ScanId；
- 计划动作 ID；
- 每个动作执行、验证、回滚结果；
- 最终状态；
- 中文摘要。

继续使用现有敏感值脱敏与 `%USERPROFILE%` 标准化。

## 测试要求

至少覆盖：

1. 直连健康时不写代理；
2. 直连失败、代理健康、`.env` 缺失时生成 `codex.proxy.env`；
3. Git/npm 冲突只在诊断确认时进入计划；
4. 写入代理后验证失败会回滚；
5. 网络恢复但 Desktop 未恢复 => `NetworkRecovered` 或 `DesktopRestartFailed`；
6. 网络+Desktop 均验证通过 => `Recovered`；
7. DNS/TLS/代理失败得到稳定分类；
8. 主界面存在 `Reconnecting 自愈`；
9. 报告包含自愈结果且继续脱敏；
10. V8.2.0 发布门禁保持单文件、自包含、管理员 manifest、无运行时 PowerShell、SHA256。
