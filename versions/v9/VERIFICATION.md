## 已取得的证据

1. V8 缺陷复现：在临时 .env 中写入带空格的 HTTP_PROXY/HTTPS_PROXY，旧 RepairService.WriteCodexProxyEnv 执行后仍残留旧端口；测试实际抛错。
2. V9 行为测试：`dotnet run --project versions/v9/tests/Tests.csproj -c Release`，31 通过、0 失败。含真实文件改写/备份/回滚、重复幂等、验证失败回滚、取消回滚、普通 HTTP 服务拒绝、真实 Git 配置清理、进程超时、真实 Junction 迁移与恢复、错误链接拒绝。
3. 真实代理集成：沙箱内受网络限制未找到可用代理；在沙箱外同一测试运行成功，选中 `http://127.0.0.1:7897`，检查 8 个候选，配置写入并重读复检成功。整个集成测试只写临时测试目录。
4. 窗口交互：`ui-tests` 创建自己的 WinForms 设置窗口；LanguageService 实际打开 Settings、选中简体中文并验证、再选中英文并验证。测试发现了初始窗口就绪和下拉内容异步加载时序问题，加入就绪等待、选项轮询和收起处理后通过。
5. 最终独立发布：`Build.ps1` 全流程通过，包含行为测试、UI 夹具构建/交互、自包含 win-x64 发布、实际 EXE `--self-test`、单 EXE 目录断言与 SHA256。
6. V8 原生历史回归通过。仅调整一条根 README 发布合同，允许 V8.2.0 被标记为历史版本；不修改其产品代码或历史发布资产。
7. V9 主界面经窗口渲染和图像检查，按钮与路径区域可见，没有旧版通过反射附加按钮的流程。
